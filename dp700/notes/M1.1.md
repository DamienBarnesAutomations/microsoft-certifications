# Dataflows Gen2

Dataflows Gen2 are a **Power Query Online-based ETL tool** inside Microsoft Fabric for extracting, transforming, and loading data from external sources into Fabric data stores. They are the successor to Dataflows Gen1 in Power BI and differ significantly in capability and destination support.

---

## What Makes Gen2 Different from Gen1

| Feature | Dataflows Gen1 | Dataflows Gen2 |
|---|---|---|
| Data destinations | Power BI datasets only | Lakehouse, Warehouse, SQL Database, Azure SQL, Azure Data Explorer, Azure Synapse |
| Staging | No | Yes — staging lakehouse used internally |
| Pipeline integration | Limited | Full — can be called as a Pipeline activity |
| Output format | In-memory dataset | Physical table in destination |
| Fabric workspace required | No | **Yes** |

> **Exam Tip:** Gen1 dataflows load into Power BI semantic models. Gen2 dataflows write to physical storage. If a question asks which tool writes transformed data to a lakehouse table with no code, the answer is Dataflows Gen2.

---

## Supported Data Destinations

- **Microsoft Fabric Lakehouse** (table, not Files section)
- **Microsoft Fabric Warehouse**
- **Microsoft Fabric SQL Database**
- **Azure SQL Database**
- **Azure Data Explorer (Kusto)**
- **Azure Synapse Analytics**

> **Exam Tip:** Destinations are configured per-query, not per-dataflow. Each query in a dataflow can have a different destination. Not every query *must* have a destination — destination is optional.

---

## Key Behaviours and Limits

- Require a **Fabric capacity workspace** (not a Free or Pro workspace)
- **Row-level security (RLS) is not supported** — dataflows cannot enforce RLS on the data they produce
- Data preview in Power Query Online shows only a **subset of rows**, not the full dataset
- Transformations are stored as **M code** (accessible via Advanced Editor)
- Each applied transformation step is visible in the **Query Settings pane**
- A query can be **disabled from loading** — useful when a query is an intermediate step only
- Queries can be **duplicated** (copy of the query, independent) or **referenced** (logical dependency on source query)

---

## Query Folding

Query folding is the ability to push transformation logic back to the source system as a native query (e.g., a SQL WHERE clause) rather than pulling all data and filtering in Power Query. When folding is supported, it drastically reduces data transfer.

- Not all sources support query folding
- You can **view the native query** from the Query Settings pane when folding is active
- Breaking the fold chain (e.g., adding a step the source can't translate) forces all subsequent steps to run in Power Query

---

## Integration with Data Pipelines

Dataflows Gen2 can be invoked as an **activity inside a Data Pipeline**. This enables:
- Running a dataflow as part of a larger orchestrated process
- Chaining dataflow completion with downstream activities (e.g., stored procedure, notebook)
- Scheduling via pipeline triggers instead of the dataflow's own refresh schedule

**When to use dataflow-in-pipeline vs standalone dataflow:**
- Use **standalone** when the dataflow is your only step and you want a simple scheduled refresh
- Use **pipeline-embedded** when you need conditional logic, retry policies, notifications, or post-load steps

---

## ETL vs ELT with Dataflows Gen2

| Pattern | How |
|---|---|
| **ETL** | Dataflow extracts → transforms → loads to destination in one step |
| **ELT** | Pipeline copies raw data to lakehouse → Dataflow connects to lakehouse and transforms → serves semantic model |

The ELT pattern is useful when raw data preservation matters or the source is slow and you want to snapshot it before transforming.

---

## When to Use Dataflows Gen2 vs Alternatives

| Need | Best Tool |
|---|---|
| Low-code transformation, multiple sources, write to lakehouse table | **Dataflows Gen2** |
| Copy data with no transformation | **Copy Data activity in Pipeline** |
| Complex transformation logic, large scale | **Spark Notebook** |
| Reusable transformation logic for Power BI analysts | **Dataflows Gen2** (dataflow as semantic model source) |
| Full orchestration with branching/looping | **Data Pipeline** |

## Common Exam Traps

**"Dataflows replace data warehouses"** — False. The raw source explicitly states they are not a replacement for a data warehouse.

**"You can use Dataflows Gen2 in any workspace"** — False. A Fabric capacity workspace is required.

**"Row-level security can be applied in a Dataflow"** — False. RLS is not supported.

**"Every query must have a destination"** — False. Destination is optional per query. A query without a destination still runs its transformations; the result just isn't persisted.

**"Dataflow refresh and pipeline trigger are the same"** — Not exactly. A dataflow has its own refresh schedule, but when embedded in a pipeline, the pipeline's trigger drives it. Both can exist simultaneously, but pipeline-triggered runs are separate from dataflow-scheduled runs.
