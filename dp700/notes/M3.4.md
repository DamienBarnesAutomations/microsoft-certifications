# Real-Time Dashboards in Microsoft Fabric

**Real-Time Dashboards** are a Fabric item that displays auto-refreshing visualisations backed by KQL queries against Eventhouse/KQL databases. Unlike static Power BI reports, they are designed for live operational monitoring.

---

## Key Characteristics

- Connected to **KQL databases** (not lakehouses or warehouses)
- Tiles auto-refresh at a configurable interval
- Supports **parameters** for user-interactive filtering
- Supports **base queries** to avoid duplicating logic across tiles
- **Two identity modes** control who the data is queried as

---

## Creating a Dashboard

1. Ensure you have a KQL database with data
2. Create a **Real-Time Dashboard** item in the workspace
3. Add a **data source** — connects to a KQL database, selecting identity mode
4. Add **tiles** — each tile is a KQL query + visualisation

---

## Identity Modes for Data Sources

When configuring a data source on a dashboard, you choose how data access is authenticated:

| Mode | Description |
|---|---|
| **Pass-through identity** | Each viewer's own permissions are used to query the data |
| **Dashboard editor's identity** | All viewers query data using the dashboard creator's permissions |

> **Exam Tip:** Use **pass-through identity** when you need per-user data visibility (viewers can only see data they have access to). Use **editor's identity** when all viewers should see the same data regardless of their individual permissions — acts like a service account. This is a favourite exam distinction.

## Tiles

Each tile:
1. Runs a **KQL query** against the data source
2. Displays results as a **visualisation** (table, bar chart, line chart, pie chart, map, stat, etc.)
3. Can use **dashboard parameters** via variable references

### Example Tile Query
```kql
bikes
| where ingestion_time() between (ago(30min) .. now())
| summarize latest_observation = arg_max(ingestion_time(), *) by Neighbourhood
| project Neighbourhood, latest_observation, No_Bikes, No_Empty_Docks
| order by Neighbourhood asc
```

## Parameters

Parameters add interactivity — viewers can filter the dashboard without editing it.

### Creating a Parameter
- Assign a **variable name** with underscore prefix convention (e.g., `_selected_city`)
- Value source: **static list** (fixed options) or **query-based** (dynamic values from KQL)
- Configure whether multiple values can be selected

### Referencing in Tile Queries
```kql
bikes
| where ingestion_time() between (ago(30min) .. now())
    and (isempty(_selected_neighbourhoods) or Neighbourhood in (_selected_neighbourhoods))
| summarize latest_observation = arg_max(ingestion_time(), *) by Neighbourhood
```

The `isempty()` check is the standard pattern: when no parameter value is selected, show all data; when values are selected, filter to them.

> **Exam Tip:** Dashboard parameters reference the variable with its **underscore-prefixed name** directly in the KQL query (e.g., `_selected_neighbourhoods`). They do not use `@` or `$` prefixes like other query parameter styles. Confusing this with T-SQL parameter syntax (`@param`) is a common mistake.

## Auto Refresh

- Dashboard editors set a **default refresh rate** and optionally a **minimum refresh rate**
- The minimum rate **prevents viewers from refreshing too frequently** and consuming excessive query resources
- Viewers can adjust the refresh rate within the allowed range during their session

> **Exam Tip:** The **minimum refresh rate** is a guard set by the editor. If the minimum is 5 minutes, a viewer cannot set refresh faster than 5 minutes. This prevents resource abuse from high-frequency manual refreshes.

## Base Queries

When multiple tiles use similar underlying KQL logic, define a **base query** to centralise it:

1. Open dashboard → Base queries menu
2. Define a query with a variable name (e.g., `_base_bike_data`)
3. Reference in tile queries as if it were a table:

```kql
// Base query (defined once)
_base_bike_data:
bikes
| where ingestion_time() between (ago(30min) .. now())
| summarize latest_observation = arg_max(ingestion_time(), *) by Neighbourhood

// Tile 1 uses base query
_base_bike_data
| project Neighbourhood, No_Bikes
| order by No_Bikes desc

// Tile 2 uses the same base query
_base_bike_data
| project Neighbourhood, No_Empty_Docks
| where No_Empty_Docks > 5
```

> **Exam Tip:** Base queries are **evaluated per tile** at query time — they are not materialised or cached. Two tiles using the same base query will each execute the full base query independently. For true materialisation, use **Materialized Views** in the KQL database instead.

---

## Pages

A Real-Time Dashboard can have **multiple pages** to organise tiles by topic, data source, or audience. Each page is an independent layout of tiles. Navigation between pages is a simple tab click.

---

## Real-Time Dashboard vs Power BI Report

| | Real-Time Dashboard | Power BI Report |
|---|---|---|
| Data source | KQL database only | Many sources (semantic model, Direct Query, etc.) |
| Refresh | Auto-refresh (seconds to minutes) | Scheduled refresh (minutes to hours) |
| Interactivity | Parameters + filters | Slicers, drill-through, cross-filter |
| Visualisations | Basic (chart, table, map, stat) | Rich (100+ visuals, custom visuals) |
| Best for | Operational monitoring, real-time | Business intelligence, ad-hoc analysis |

## Common Exam Traps

**"Base queries are cached/materialised"** — False. Each tile re-executes the base query independently. For materialisation, use KQL database Materialized Views.

**"Pass-through identity lets everyone see all data"** — False. Each viewer's own permissions apply — some viewers may see less data if they lack permission to underlying records.

**"Auto-refresh minimum rate limits how slow viewers can set refresh"** — Wrong direction. The minimum rate limits how **fast** (frequent) the refresh can be. Editors set it to prevent resource overuse, not to enforce a maximum interval.

**"Real-Time Dashboards can connect to lakehouses"** — False. Only KQL databases (in an Eventhouse) are supported as data sources for Real-Time Dashboards.
