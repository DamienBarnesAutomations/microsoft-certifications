# Querying a Fabric Data Warehouse

This module covers the T-SQL query capabilities in a Fabric Warehouse — what works, what doesn't, cross-database queries, and query patterns for analytical workloads.

---

## Supported T-SQL Subset

Fabric Warehouse supports a broad subset of T-SQL, but not everything from SQL Server. Key supported features:

**Supported:**
- `SELECT`, `FROM`, `WHERE`, `GROUP BY`, `ORDER BY`, `HAVING`
- `JOIN` (INNER, LEFT/RIGHT/FULL OUTER, CROSS)
- `UNION`, `UNION ALL`, `INTERSECT`, `EXCEPT`
- `CTEs` (WITH clause)
- Window functions (`ROW_NUMBER`, `RANK`, `DENSE_RANK`, `NTILE`, `LAG`, `LEAD`, `FIRST_VALUE`, `LAST_VALUE`)
- Aggregate functions (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`, `STRING_AGG`)
- `CASE` expressions
- Subqueries
- `CREATE TABLE`, `DROP TABLE`, `ALTER TABLE`
- `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `MERGE`
- `CREATE VIEW`, `ALTER VIEW`, `DROP VIEW`
- `CREATE PROCEDURE`, `ALTER PROCEDURE`, `DROP PROCEDURE`, `EXEC`
- `BEGIN TRANSACTION`, `COMMIT`, `ROLLBACK`
- `COPY INTO`

**Not supported (key ones):**
- Traditional indexes (`CREATE INDEX`, `CREATE CLUSTERED INDEX`)
- `SELECT INTO` — use CTAS instead (`CREATE TABLE ... AS SELECT`)
- Triggers
- User-defined types (UDT)
- `IDENTITY` columns with custom seed/increment
- Certain data types (spatial types, XML with schemas, hierarchyid)

> **Exam Tip:** `SELECT INTO` is not supported in Fabric Warehouse. Use `CREATE TABLE ... AS SELECT` (CTAS) instead. This is a common porting gotcha from SQL Server.

## Common Query Patterns

### Window Functions
Essential for analytical queries:

```sql
-- Rank products by revenue within each category
SELECT
    ProductID,
    Category,
    TotalRevenue,
    ROW_NUMBER() OVER (PARTITION BY Category ORDER BY TotalRevenue DESC) AS RankInCategory,
    RANK() OVER (ORDER BY TotalRevenue DESC) AS OverallRank,
    SUM(TotalRevenue) OVER (PARTITION BY Category) AS CategoryTotal,
    TotalRevenue * 1.0 / SUM(TotalRevenue) OVER (PARTITION BY Category) AS CategoryShare
FROM dbo.ProductRevenue;
```

**ROW_NUMBER vs RANK vs DENSE_RANK:**
| Function | Ties | Gaps |
|---|---|---|
| `ROW_NUMBER()` | Assigns unique numbers (arbitrary tiebreak) | No gaps |
| `RANK()` | Assigns same rank to ties | Gaps after ties (1,1,3) |
| `DENSE_RANK()` | Assigns same rank to ties | No gaps (1,1,2) |

### Running Totals
```sql
SELECT
    SaleDate,
    DailyRevenue,
    SUM(DailyRevenue) OVER (ORDER BY SaleDate ROWS UNBOUNDED PRECEDING) AS RunningTotal
FROM dbo.DailyRevenue;
```

### Period-over-Period Comparison with LAG/LEAD
```sql
SELECT
    SaleMonth,
    Revenue,
    LAG(Revenue, 1) OVER (ORDER BY SaleMonth) AS PreviousMonth,
    Revenue - LAG(Revenue, 1) OVER (ORDER BY SaleMonth) AS MonthOverMonthChange
FROM dbo.MonthlyRevenue;
```

## CTEs (Common Table Expressions)

```sql
WITH CustomerRevenue AS (
    SELECT CustomerID, SUM(Amount) AS TotalRevenue
    FROM dbo.FactSales
    GROUP BY CustomerID
),
CustomerTiers AS (
    SELECT
        CustomerID,
        TotalRevenue,
        CASE
            WHEN TotalRevenue > 10000 THEN 'Gold'
            WHEN TotalRevenue > 5000 THEN 'Silver'
            ELSE 'Bronze'
        END AS Tier
    FROM CustomerRevenue
)
SELECT Tier, COUNT(*) AS CustomerCount, AVG(TotalRevenue) AS AvgRevenue
FROM CustomerTiers
GROUP BY Tier;
```

Recursive CTEs are supported for hierarchical data (org charts, bill of materials).

## Cross-Database Queries

Query across multiple Fabric items in the same workspace using three-part names:

```sql
-- Query Lakehouse table from Warehouse context
SELECT c.CustomerName, s.Amount
FROM [SalesWarehouse].[dbo].[FactSales] AS s
JOIN [CustomerLakehouse].[dbo].[silver_customers] AS c
    ON s.CustomerID = c.CustomerID;

-- Query another Warehouse
SELECT *
FROM [ReportingWarehouse].[dbo].[DimDate]
WHERE DateKey >= 20240101;
```

**Format:** `[ItemName].[SchemaName].[TableName]`

> **Exam Tip:** Cross-database queries in Fabric work **within the same workspace only**. To reference data from another workspace, create a **shortcut** that mirrors that data into the current workspace's lakehouse.

## Views for Security and Abstraction

```sql
-- Row-filtered view (expose only active customers)
CREATE VIEW dbo.vw_ActiveCustomers AS
SELECT CustomerID, CustomerName, Email, City
FROM dbo.DimCustomer
WHERE IsActive = 1;

-- Column-filtered view (hide sensitive fields)
CREATE VIEW dbo.vw_CustomerPublic AS
SELECT CustomerID, CustomerName, City
FROM dbo.DimCustomer;
-- Email not exposed
```

Views are the primary way to implement **column-level and row-level filtering** for analysts who shouldn't see all data.

## Stored Procedures for ETL Logic

```sql
CREATE PROCEDURE dbo.usp_RefreshDimProduct
AS
BEGIN
    TRUNCATE TABLE dbo.Staging_Products;
    
    COPY INTO dbo.Staging_Products
    FROM 'https://storage.blob.core.windows.net/raw/products.parquet'
    WITH (FILE_TYPE = 'PARQUET', CREDENTIAL = (IDENTITY = 'Managed Identity'));
    
    MERGE INTO dbo.DimProduct AS target
    USING dbo.Staging_Products AS source
    ON target.ProductID = source.ProductID
    WHEN MATCHED THEN UPDATE SET target.ProductName = source.ProductName, target.Price = source.Price
    WHEN NOT MATCHED THEN INSERT VALUES (source.ProductID, source.ProductName, source.Price);
END;
```

Call from a Pipeline using the **Stored Procedure activity** — no code required in the pipeline itself.

## Query Performance Considerations

### Statistics
The optimizer relies on column statistics. Auto-created stats may be stale if data changes significantly. Manually update:
```sql
UPDATE STATISTICS dbo.FactSales;
```

### Query Insights (Monitoring)
Fabric Warehouse provides `queryinsights` views for query history analysis (covered in M4.6):
```sql
SELECT TOP 20 last_run_command, median_total_elapsed_time_ms, number_of_runs
FROM queryinsights.long_running_queries
ORDER BY median_total_elapsed_time_ms DESC;
```

## Connecting to the Warehouse

Fabric Warehouse exposes a **SQL connection string** for connecting from:
- SQL Server Management Studio (SSMS)
- Azure Data Studio
- Power BI Desktop (Direct Query or Import)
- Any ODBC/JDBC-compatible tool

Connection string format:
```
Server: {workspace-id}.datawarehouse.fabric.microsoft.com
Database: {warehouse-name}
Authentication: Azure Active Directory (MFA or Service Principal)
```

## Common Exam Traps

**"SELECT INTO works in Fabric Warehouse"** — False. Use CTAS (`CREATE TABLE ... AS SELECT`) instead.

**"Traditional CREATE INDEX improves query performance"** — Fabric Warehouse does not support traditional indexes. Use statistics, CTAS for pre-aggregation, and query design instead.

**"Cross-database queries work across workspaces"** — False. Three-part names only work within the same workspace. Use shortcuts for cross-workspace.

**"Views enforce row-level security"** — Views filter data based on their definition, but they apply the same filter to **everyone** who uses the view. True per-user RLS requires object-level permissions + views, or connecting via a semantic model that has RLS configured. The Warehouse itself does not have native RLS like SQL Server.
