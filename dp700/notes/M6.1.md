# Use Activator in Microsoft Fabric (Exam Prep)

Activator is a real-time monitoring and alerting tool in Microsoft Fabric. It evaluates changing data and event streams to trigger immediate business actions when specific patterns or conditions are detected.

---

## 1. Core Architecture & Hierarchy

Activator structures streaming event data into logical business objects to monitor distinct real-world entities.

### Object Model
- **Objects**: Represent individual instances of a business entity (e.g., `Package001`, `Freezer_B`, `Customer_123`).
- **Properties**: Attributes of an object updated dynamically as data streams in (e.g., `CurrentTemperature`, `VibrationLevel`).
- **Events**: The raw incoming records that carry fields containing values.
- **Unique Identifier**: A key column (like `DeviceID` or `PackageID`) that maps incoming event rows to their corresponding object instance.

> **Exam Tip:** Without a unique identifier, all events are treated as a single stream-wide object. To monitor entities individually (e.g., track temperature *per truck*), a unique identifier is required.

---

## 2. Setting Up Activator

The typical setup workflow for real-time alerts involves:

```
[Event Source] ➔ [Eventstream] ➔ [Activator Destination] ➔ [Object & Properties] ➔ [Rules & Actions]
```

### Steps to Ingest and Configure
1. Define an **Eventstream** in Fabric to capture streaming data.
2. Route the Eventstream to an **Activator destination**.
3. In the Activator interface, select **Create object**.
4. Choose the **unique identifier** to distinguish objects.
5. Select the **properties** (data columns) to monitor.

---

## 3. Creating Rules

Rules define the specific conditions under which an alert should be triggered. A rule configuration includes three parts:

### A. Monitor (What to watch)
- **Attribute**: Select the property column (e.g., `Temperature`).
- **Summarization**: Smooth out sensor noise using:
  - `Average`: Smooths fluctuations.
  - `Min/Max`: Captures critical peaks/valleys.
  - `Count`: Tracks event frequency (detects dead sensors).
  - `Total`: Accumulates numerical values.
- **Window and Step Size**:
  - *Window size*: The time window of historical data to evaluate (e.g., last 10 minutes of sensor readings).
  - *Step size*: How often the rule evaluates (e.g., every 5 minutes).

### B. Condition (When to act)
- **Threshold**: Triggers when a value passes a limit (e.g., `Value > 68`).
- **Change detection**: Detects sudden increases/decreases.
- **Range monitoring**: Detects entry or exit from a safe operating range.
- **Missing data**: Triggers if no events arrive within a set time (e.g., `No events for 30 minutes`).

### C. Property Filter (Narrowing scope)
Filter rules to apply only to specific subsets (e.g., `City == "Seattle"` or `ProductType == "Medicine"`).

---

## 4. Triggering Actions

Activator supports four types of downstream actions:

1. **Email Actions**: Send formatted emails via Office 365. Best for non-urgent tasks.
2. **Teams Actions**: Direct-message channels or specific users. Best for real-time team coordination.
3. **Power Automate Actions**: Kick off complex business workflows across third-party software (e.g., create a support ticket in Salesforce).
4. **Fabric Item Actions**: Trigger data engineering operations, such as running a **Data Pipeline** or executing a **Spark Notebook** to clean data.

---

## Common Exam Traps

- **"Activator uses KQL queries to evaluate rules"** — False. Activator has a built-in visual editor for rules. KQL is used in Eventhouses, not Activator, though Eventhouse query results can trigger Activator.
- **"Every event that matches a condition triggers a new email"** — False by default. Activator's state management tracks object transitions. An alert is sent when the condition *becomes* true (enters the state), avoiding alert storms unless configured for recurring notifications.
- **"Activator alerts poll tables on a timer"** — False. Activator is event-driven and evaluates rules as events flow through the Eventstream.
