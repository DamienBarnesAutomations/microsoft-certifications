# Microsoft Fabric Data Warehouse

A **Fabric Data Warehouse** is a fully managed, cloud-native T-SQL analytical store built on OneLake. It provides complete SQL DML (SELECT, INSERT, UPDATE, DELETE, MERGE) and DDL capabilities — unlike the Lakehouse's read-only SQL endpoint.

---

## Warehouse vs Lakehouse SQL Endpoint

| Capability | Warehouse | Lakehouse SQL Endpoint |
|---|---|---|
| SELECT | ✅ | ✅ |
| INSERT / UPDATE / DELETE | ✅ | ❌ |
| CREATE TABLE | ✅ | ❌ (via Spark only) |
| Stored Procedures | ✅ | ❌ |
| Views | ✅ | ✅ (read-only) |
| Transactions | ✅ | Limited |
| T-SQL syntax | Full T-SQL | Subset only |

> **Exam Tip:** The Lakehouse SQL endpoint is **read-only**. All writes to a lakehouse must go through Spark, Pipelines, or Dataflows. If a question asks which Fabric item supports T-SQL INSERT statements, the answer is **Warehouse**, not Lakehouse.

---

## Warehouse Storage

Fabric Warehouses store data in **Parquet files on OneLake** (using Delta Lake format internally). This means:
- Warehouse data is readable by Spark (via OneLake path or shortcut)
- Data is not locked into a proprietary format
- External tools can access warehouse data via the OneLake API

---

## Cross-Database Queries

Fabric Warehouses support **cross-database querying** within the same workspace using three-part naming:

```sql
SELECT w.OrderID, l.CustomerName
FROM [WarehouseName].[dbo].[Orders] AS w
JOIN [LakehouseName].[dbo].[Customers] AS l
    ON w.CustomerID = l.CustomerID
```

- Query a **Warehouse** from another Warehouse in the same workspace
- Query a **Lakehouse** SQL endpoint from a Warehouse (read-only access to lakehouse tables)

> **Exam Tip:** Cross-database queries work **within the same workspace only**. You cannot query across workspaces directly via T-SQL. To access data from another workspace, use a shortcut.

## Creating Tables

```sql
-- Standard table
CREATE TABLE dbo.FactSales (
    SaleID          INT             NOT NULL,
    ProductID       INT             NOT NULL,
    CustomerID      INT             NOT NULL,
    SaleDate        DATE            NOT NULL,
    Quantity        INT             NOT NULL,
    Amount          DECIMAL(18,2)   NOT NULL
);

-- CREATE TABLE AS SELECT (CTAS) — creates and populates in one step
CREATE TABLE dbo.SalesSummary
AS
SELECT ProductID, SUM(Amount) AS TotalAmount, COUNT(*) AS TransactionCount
FROM dbo.FactSales
GROUP BY ProductID;
```

## Loading Data into a Warehouse

### COPY INTO (T-SQL Bulk Load)
```sql
COPY INTO dbo.FactSales
FROM 'https://storageaccount.blob.core.windows.net/container/sales/*.parquet'
WITH (
    FILE_TYPE = 'PARQUET',
    CREDENTIAL = (IDENTITY = 'Managed Identity')
);
```

> **Exam Tip:** `COPY INTO` is the **fastest way** to load large volumes of data from Azure Storage (Parquet, CSV, ORC) into a Fabric Warehouse. It uses parallelised bulk operations. This is preferred over INSERT...SELECT for large loads.

### Via Pipeline Copy Data Activity
- Source: any supported connector
- Destination: Warehouse table
- The Copy Data activity internally uses bulk load for Warehouse destinations

### Via Dataflow Gen2
- Configure a data destination pointing to a Warehouse table
- Useful for lower-code scenarios

## Indexes, Statistics, and Distributions

Fabric Warehouses are a **distributed SQL engine** — unlike traditional SQL Server, data is distributed across compute nodes.

### Table Distributions
Fabric Warehouse uses **round-robin distribution** by default (rows distributed evenly across nodes). Unlike Azure Synapse Analytics (which also supports hash distribution and replicated tables), Fabric Warehouse currently manages distribution automatically.

### Statistics
The query optimizer uses **column statistics** to estimate row counts and choose execution plans. Statistics are **auto-created** when queries reference columns without existing statistics.

Manually create or update statistics when data distribution changes significantly:
```sql
CREATE STATISTICS stats_CustomerID ON dbo.FactSales (CustomerID);
UPDATE STATISTICS dbo.FactSales;
```

### No Traditional Indexes
Fabric Warehouses do not support traditional B-tree indexes (clustered/non-clustered). Query performance relies on:
- Column statistics
- Partitioning (limited)
- Query optimization by the engine
- CTAS to pre-materialise complex queries

## Transactions

Fabric Warehouse supports explicit transactions:
```sql
BEGIN TRANSACTION;
    INSERT INTO dbo.FactSales VALUES (...);
    UPDATE dbo.DimProduct SET Stock = Stock - 1 WHERE ProductID = 101;
COMMIT;

-- Or rollback on error
BEGIN TRANSACTION;
    DELETE FROM dbo.FactSales WHERE SaleDate < '2020-01-01';
ROLLBACK;  -- Undo the delete
```

## Views and Stored Procedures

```sql
-- Create a view
CREATE VIEW dbo.vw_SalesSummary AS
SELECT ProductID, SUM(Amount) AS TotalRevenue
FROM dbo.FactSales
GROUP BY ProductID;

-- Stored procedure
CREATE PROCEDURE dbo.usp_LoadDailySales @LoadDate DATE
AS
BEGIN
    INSERT INTO dbo.FactSales
    SELECT * FROM dbo.StagingSales WHERE SaleDate = @LoadDate;
    
    DELETE FROM dbo.StagingSales WHERE SaleDate = @LoadDate;
END;
```

## Workspace Hub and Cross-Workspace Access

The **Workspace Hub** in a Fabric warehouse allows you to view tables from Lakehouse items in the same workspace — making cross-item querying easier to discover and use. This is still constrained to the same workspace boundary.

---

## Warehouse vs Azure Synapse Analytics Dedicated Pool

| | Fabric Warehouse | Synapse Dedicated Pool |
|---|---|---|
| Management | Fully managed (no cluster sizing) | Requires DWU provisioning |
| Storage | OneLake (Parquet/Delta) | Synapse internal (not open format) |
| Distribution | Automatic | Manual (hash, round-robin, replicated) |
| Integration | Native Fabric (same platform as lakehouse) | Separate Azure service |
| Pause/Resume | Not applicable (serverless-like billing) | Explicit pause/resume |
| COPY INTO | ✅ | ✅ |

## Common Exam Traps

**"Fabric Warehouse and Lakehouse SQL endpoint both support full T-SQL"** — False. Lakehouse SQL endpoint is read-only. Full T-SQL DML requires a Warehouse.

**"COPY INTO requires a SAS token"** — Not necessarily. Managed Identity is the preferred authentication method. SAS tokens are an alternative.

**"Fabric Warehouse stores data in SQL Server file format"** — False. Data is stored as Parquet on OneLake, making it accessible to Spark and other tools.

**"Cross-database queries work across workspaces"** — False. Only within the same workspace via three-part naming. Cross-workspace access requires shortcuts or data movement.

**"You must manually create indexes in Fabric Warehouse"** — False. Fabric Warehouse does not use traditional indexes. The engine handles query optimization automatically.
