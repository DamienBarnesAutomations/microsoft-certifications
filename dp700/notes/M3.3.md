# KQL — Writing Queries for Real-Time Analytics

KQL (Kusto Query Language) is the query language for Fabric's Eventhouse and KQL databases. It is purpose-built for time-series and log data. This module is a query-focused deep dive for exam preparation.

---

## KQL Query Structure

Every KQL query is a **pipeline of operators** separated by `|`:

```kql
TableName
| operator1 arguments
| operator2 arguments
| ...
```

- Reads left-to-right / top-to-bottom
- Each operator receives the output of the previous one
- Operators are **case-insensitive** but table/column names are **case-sensitive**
- Comments: `//` single line

---

## Filtering: where

```kql
Events | where EventType == "error"
Events | where Timestamp > ago(1h)
Events | where Duration between (100 .. 500)           // inclusive range
Events | where EventType in ("error", "warning")
Events | where EventType !in ("debug", "trace")
Events | where isnotnull(UserID)
Events | where isempty(ErrorCode)
Events | where EventDescription contains "timeout"     // substring match
Events | where EventDescription startswith "HTTP"
Events | where EventDescription matches regex @"\d{3}-\d{4}"
```

**`ago()` time arithmetic:**
```kql
ago(1h)     // 1 hour ago
ago(30m)    // 30 minutes ago
ago(7d)     // 7 days ago
ago(2h30m)  // 2 hours 30 minutes ago
```

## Projection: project, extend, project-away, project-rename

```kql
// Select specific columns (all others dropped)
Events | project Timestamp, EventType, UserID

// Add computed column (keeps existing columns)
Events | extend DurationSec = Duration / 1000.0

// Add multiple computed columns
Events | extend
    DurationSec = Duration / 1000.0,
    IsError = EventType == "error",
    HourOfDay = hourofday(Timestamp)

// Drop specific columns (keep all others)
Events | project-away InternalField, DebugPayload

// Rename columns
Events | project-rename EventTimestamp = Timestamp, UserIdentifier = UserID
```

## Aggregation: summarize

```kql
Events
| summarize
    TotalEvents = count(),
    ErrorCount = countif(EventType == "error"),
    AvgDuration = avg(Duration),
    MaxDuration = max(Duration),
    UniqueUsers = dcount(UserID)
  by EventType, bin(Timestamp, 1h)
```

**Aggregate functions:**
| Function | Description |
|---|---|
| `count()` | Total rows |
| `countif(condition)` | Rows matching condition |
| `dcount(col)` | Approximate distinct count |
| `dcountif(col, condition)` | Approximate distinct count with filter |
| `sum(col)` | Sum |
| `avg(col)` | Average |
| `min(col)` / `max(col)` | Min/Max |
| `percentile(col, N)` | Nth percentile |
| `stdev(col)` | Standard deviation |
| `make_list(col)` | Collect values into a dynamic array |
| `make_set(col)` | Collect distinct values into an array |
| `arg_max(col, *)` | All columns from row where col is maximum |
| `arg_min(col, *)` | All columns from row where col is minimum |

> **Exam Tip:** `dcount()` is an **approximate** distinct count using HyperLogLog. For exact distinct counts use `count(distinct col)` — but this is slower. The exam may ask which function gives an approximate vs exact distinct count.

## Time Series with bin()

`bin()` rounds values down to the nearest multiple of the specified step:

```kql
// Events per 5 minutes
Events
| summarize Count = count() by bin(Timestamp, 5m)
| render timechart

// Events per day
Events
| summarize Count = count() by bin(Timestamp, 1d)
```

> **Exam Tip:** `bin()` rounds **down**, not to nearest. `bin(09:07, 5m)` → `09:05`. Gaps in the time series (no events in a window) appear as missing rows. Use `make-series` instead of `summarize` + `bin` if you need gaps filled with zeros/nulls.

---

## make-series (Time Series with Gap Filling)

```kql
Events
| make-series EventCount = count() on Timestamp from ago(7d) to now() step 1h by EventType
// Returns arrays of timestamps and corresponding counts, one row per EventType
// Gaps are filled with 0 (count) or null (avg) automatically
```

## Joins in KQL

```kql
Devices
| join kind=inner (
    Alerts | where Severity == "High"
) on DeviceID
```

**Join kinds:**
| Kind | Description |
|---|---|
| `inner` | Rows matching in both tables |
| `leftouter` | All left rows; matched right or null |
| `rightouter` | All right rows; matched left or null |
| `fullouter` | All rows from both, matched or null |
| `leftsemi` | Left rows that have a match in right (no right columns) |
| `leftanti` | Left rows that have NO match in right |

## let — Variables and Subqueries

```kql
let threshold = 1000;
let errorEvents = Events | where EventType == "error" and Duration > threshold;

errorEvents
| summarize Count = count() by DeviceID
| top 10 by Count desc
```

`let` defines reusable named expressions within a query. Tabular `let` statements are like subqueries — they don't materialise until referenced.

## parse and extract — Working with String Data

```kql
// Extract fields from a log string
Events
| parse EventMessage with "User=" UserName " Action=" Action " Duration=" Duration:int " ms"

// Regex extraction
Events
| extend IPAddress = extract(@"(\d+\.\d+\.\d+\.\d+)", 1, EventMessage)
```

## Working with dynamic (JSON) Fields

```kql
// Access nested field
Events | project Payload.temperature, Payload.humidity

// Check if field exists
Events | where isnotnull(Payload.errorCode)

// Expand array field into rows
Events
| mv-expand Payload.tags
| project Payload_tags
```

`mv-expand` is the key operator for **flattening arrays** — each array element becomes its own row. Essential when events contain arrays of tags, errors, or measurements.

## Functions

User-defined functions for reusable query logic:

```kql
// Create a stored function
.create function GetRecentErrors(lookback:timespan) {
    Events
    | where EventType == "error" and Timestamp > ago(lookback)
}

// Call it
GetRecentErrors(1h)
| summarize count() by DeviceID
```

---

## Stored Query Results

Materialise the results of a query for later reuse (within the same session):

```kql
.set-or-replace MyQueryResults <|
    Events
    | summarize Count = count() by EventType, bin(Timestamp, 1h)
// Results stored as a table named MyQueryResults
```

## Common Exam Traps

**"`bin()` fills gaps in time series"** — False. `bin()` only rounds timestamps. Gaps (no events in a window) result in missing rows. Use `make-series` for gap-filling.

**"`dcount()` gives exact distinct counts"** — False. It uses an approximate algorithm (HyperLogLog). For exact counts, use `count(distinct column)`.

**"KQL joins always return all columns from both tables"** — Depends on join kind. `leftsemi` only returns left-table columns. `inner` returns columns from both.

**"`mv-expand` filters the table"** — No, it expands rows. If a row has an array with 3 elements, after `mv-expand` it becomes 3 rows. The total row count can only increase (or stay the same for empty arrays).

**"KQL is case-insensitive throughout"** — Operators are case-insensitive, but table names, column names, and string comparisons are **case-sensitive** by default. Use `=~` instead of `==` for case-insensitive string comparison.
