# Ingesting Data with Spark and Delta Lake

This module focuses on ingestion patterns — how to get data from external sources into the lakehouse efficiently using Spark, and how to design incremental loads.

---

## Ingestion Patterns Overview

| Pattern | Approach | When to Use |
|---|---|---|
| **Full Load** | Replace all data each run | Small datasets, no history needed |
| **Incremental / Append** | Add only new records | Event data, append-only sources |
| **Upsert (SCD Type 1)** | Insert new, update changed | Slowly changing dimensions, operational sync |
| **SCD Type 2** | Insert new version with date ranges | History-preserving dimension tables |
| **ELT** | Load raw → transform in-place | Preserve raw data, complex transformations |

---

## Full Load Pattern

```python
# Read from source
source_df = spark.read.jdbc(
    url="jdbc:sqlserver://server.database.windows.net:1433;database=OperationsDB",
    table="dbo.Products",
    properties={"user": "admin", "password": "...", "driver": "com.microsoft.sqlserver.jdbc.SQLServerDriver"}
)

# Overwrite the target table completely
source_df.write.format("delta").mode("overwrite").saveAsTable("silver_products")
```

> **Exam Tip:** Using `mode("overwrite")` with Delta tables rewrites the data but **preserves the schema** by default. To change schema on overwrite, add `.option("overwriteSchema", "true")`. Without that option, a schema mismatch will throw an error.

## Incremental Append Pattern

Loading only records created or modified since the last run. Requires a **watermark column** — typically a `CreatedAt` or `ModifiedAt` timestamp.

```python
# Read last watermark from a control table
last_watermark = spark.sql("SELECT MAX(LastLoadTime) FROM control.ingestion_watermarks WHERE TableName = 'Orders'").collect()[0][0]

# Load only new records
new_orders = spark.read.jdbc(
    url=jdbc_url,
    table=f"(SELECT * FROM dbo.Orders WHERE ModifiedAt > '{last_watermark}') AS incremental",
    properties=jdbc_props
)

# Append to Delta table
new_orders.write.format("delta").mode("append").saveAsTable("silver_orders")

# Update watermark
spark.sql(f"UPDATE control.ingestion_watermarks SET LastLoadTime = NOW() WHERE TableName = 'Orders'")
```

## Upsert Pattern (MERGE)

For sources where records can be both inserted and updated (operational databases, CRMs):

```python
from delta.tables import DeltaTable

# Load staging data
staging = spark.read.jdbc(url=jdbc_url, table="dbo.Customers", properties=jdbc_props)

# Merge into target
target = DeltaTable.forName(spark, "silver_customers")
target.alias("t").merge(
    staging.alias("s"),
    "t.CustomerID = s.CustomerID"
).whenMatchedUpdateAll() \
 .whenNotMatchedInsertAll() \
 .execute()
```

## SCD Type 2 Pattern

Preserves full history by adding a new row for each change, with `ValidFrom` / `ValidTo` date range columns.

```python
from pyspark.sql.functions import current_timestamp, lit

# Identify changed records
changes = staging.join(target_df, "CustomerID") \
    .filter(staging["Email"] != target_df["Email"])

# Expire old records (set ValidTo)
target.alias("t").merge(
    changes.alias("c"),
    "t.CustomerID = c.CustomerID AND t.IsCurrent = true"
).whenMatchedUpdate(set={
    "IsCurrent": lit(False),
    "ValidTo": current_timestamp()
}).execute()

# Insert new versions
new_versions = changes.withColumn("IsCurrent", lit(True)) \
    .withColumn("ValidFrom", current_timestamp()) \
    .withColumn("ValidTo", lit(None).cast("timestamp"))

new_versions.write.format("delta").mode("append").saveAsTable("silver_customers")
```

## Reading from External Sources

### JDBC (SQL databases)
```python
df = spark.read.jdbc(
    url="jdbc:sqlserver://...",
    table="dbo.Orders",
    properties={"user": "...", "password": "..."}
)

# For large tables: parallelise the read using column bounds
df = spark.read.jdbc(
    url=jdbc_url,
    table="dbo.Orders",
    column="OrderID",         # Numeric column to split on
    lowerBound=1,
    upperBound=1000000,
    numPartitions=10,         # Number of parallel reads
    properties=jdbc_props
)
```

> **Exam Tip:** Without `numPartitions`, Spark reads a JDBC table with a **single partition** — one connection, no parallelism. For large tables this is slow. Setting `numPartitions` with `column`, `lowerBound`, and `upperBound` enables parallel reads. The column should be a **uniformly distributed numeric or date column** (e.g., auto-increment ID or date).

### REST APIs / HTTP Sources
No native Spark connector — typically:
1. Read via Python `requests` library in a notebook cell
2. Convert to a Spark DataFrame: `spark.createDataFrame(pandas_df)`
3. For large paginated APIs, loop pages and union DataFrames

### Files on OneLake / ADLS
```python
# CSV
df = spark.read.csv("abfss://workspace@onelake.dfs.fabric.microsoft.com/lakehouse.Lakehouse/Files/raw/", header=True)

# Parquet with schema inference
df = spark.read.parquet("Files/raw/events/")

# Delta
df = spark.read.format("delta").load("Files/delta/products/")
```

## Schema Validation on Ingestion

Before writing, validate that required columns exist and have expected types:

```python
from pyspark.sql.types import StructType, StructField, StringType, IntegerType

expected_schema = StructType([
    StructField("OrderID", IntegerType(), nullable=False),
    StructField("CustomerID", IntegerType(), nullable=False),
    StructField("Amount", FloatType(), nullable=True)
])

# Compare schemas
if df.schema != expected_schema:
    raise ValueError(f"Schema mismatch: {df.schema}")
```

Or use Delta's built-in schema enforcement — any write with a mismatching schema will fail automatically unless `mergeSchema` is set.

## Idempotency

An idempotent ingestion job produces the same result regardless of how many times it runs. Key techniques:
- **Full load with overwrite**: naturally idempotent
- **Incremental with MERGE**: idempotent (re-merging the same records is a no-op)
- **Incremental with append only**: NOT idempotent — re-running appends duplicates

> **Exam Tip:** Pipeline retry policies require idempotent data operations. If a pipeline fails mid-run and retries, a simple append will create duplicates. Use MERGE or overwrite patterns in automated pipelines.

## Common Exam Traps

**"Appending data is always the right pattern for incremental loads"** — Only for truly append-only sources (events, logs). For sources where records can update, append creates duplicates. Use MERGE.

**"JDBC reads are automatically parallelised"** — False. Default is single-partition (single connection). You must explicitly configure `numPartitions` for parallel reads.

**"Schema enforcement is off by default in Delta"** — False. Schema enforcement is ON by default. Mismatched writes fail unless you use `mergeSchema` or `overwriteSchema`.

**"SCD Type 1 and Type 2 serve the same purpose"** — No. Type 1 overwrites old values (no history). Type 2 preserves history by adding rows with date ranges. Choose based on whether history must be queryable.
