# Monitoring Activities in Microsoft Fabric

Monitoring ensures data ingestion, orchestration, and transformation pipelines run reliably. Fabric provides central monitoring interfaces and event-driven alerting.

---

## Fabric Monitor Hub

The **Monitor Hub** (accessed via the **Monitor** tab in the navigation pane) is a centralized visual tracking dashboard for all operations across the tenant.

### Key Capabilities
- **Cross-Item Monitoring**: Tracks pipelines, Dataflows Gen2, semantic model refreshes, Spark jobs, notebooks, and Eventstreams in one place.
- **Detailed Execution Metadata**:
  - Start/end times and total duration.
  - Success, failure, or in-progress states.
  - Job history to compare past vs. current runs.
  - Detailed error messages and logs for failures.
- **Filtering**: Filter operations by status, item type, start time, workspace, and owner.
- **Drill-Down Links**: Click on failed Spark jobs or Dataflows to inspect line-level script failures and retry tasks.

---

## Monitoring Best Practices
1. **Establish Baselines**: Regular run-time tracking helps define normal execution duration, making it easy to spot anomalies or data skew.
2. **Handle Transient Errors**: For semantic model refreshes, monitor refresh retries to distinguish network blips from true dataset failures.
3. **Optimize Computes**: Use performance metrics in the monitoring logs to detect resource bottlenecking (e.g., Spark executors throttling).

## Event Alerts with Fabric Activator

**Activator** is Microsoft Fabric's real-time event detection and rules engine. It automates responses when specific conditions occur in streaming data or system states.

### Core Concepts
- **Events**: Individual point-in-time observations (e.g., a temperature reading from a sensor).
- **Objects**: The business entity being monitored (e.g., a specific package, freezer, or customer account).
- **Properties**: Attributes of an object updated by event streams (e.g., `CurrentTemperature`).
- **Rules**: Logically defined conditions that trigger actions (e.g., "Trigger alert if average temperature > 68°F for 10 minutes").

### Alerting Actions
When a rule triggers, Activator can execute:
1. **Email notifications**: Best for non-urgent review or audit trails.
2. **Teams messages**: Best for real-time team coordination and fast response.
3. **Power Automate flows**: Best for multi-step cross-application business processes.
4. **Fabric item actions**: Automate operational tasks, such as triggering a Data Pipeline or running a Notebook in response to an anomaly.

## Common Exam Traps

- **"Workspace Viewers can see all jobs in the Monitor Hub"** — False. Users only see jobs for items they have explicit permissions to view.
- **"Activator alerts only support simple numerical thresholds"** — False. Rules can evaluate complex patterns over time windows (e.g., average over 10 mins) or evaluate KQL queries on KQL databases.
- **"Monitor Hub stores logs permanently"** — False. Monitor Hub retains job history for **30 days**. Long-term retention requires exporting logs to Azure Log Analytics.
