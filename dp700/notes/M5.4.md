# Administering Microsoft Fabric

Fabric administration spans three tiers: **tenant-level** (global settings), **capacity-level** (resource allocation), and **workspace-level** (day-to-day management). Understanding which tier controls what is critical for the exam.

---

## Admin Hierarchy

```
Microsoft Fabric Tenant
  ├── Tenant Admin (Fabric Admin portal settings)
  │
  ├── Fabric Capacity
  │     ├── Capacity Admin (scale, pause/resume, per-capacity settings)
  │     └── Workspaces assigned to this capacity
  │           └── Workspace Admin (workspace members, items, settings)
  │
  └── Entra ID (user identities, group membership, service principals)
```

---

## Tenant-Level Administration

Managed via the **Fabric Admin portal** (`app.powerbi.com/admin-portal`). Accessible only to **Fabric Administrators** (users with the Fabric Admin role in Entra ID) or **Power Platform Administrators** / **Global Administrators**.

### Key Tenant Settings
- **Workspace settings**: who can create workspaces
- **Export and sharing**: control external sharing, public embedding, email subscriptions
- **Developer settings**: embed codes, service principal access, API access
- **Sensitivity labels**: require sensitivity labels, default label behaviour
- **Capacity settings**: assign workspaces to capacities, manage capacity admins
- **Audit logs**: enable activity logging (see below)
- **Fabric items**: enable/disable specific Fabric workloads (e.g., prevent Data Factory item creation)
- **Dataflows**: allow Dataflows Gen2 (on by default)

### Audit Logs
Fabric administrator activity and user actions are logged in the **Microsoft 365 Compliance portal** (Unified Audit Log). Auditing must be enabled by an admin. Logs include:
- Who accessed which items
- Pipeline runs, report views, dataset refreshes
- Permission changes

> **Exam Tip:** Fabric audit logs are in **Microsoft 365 Compliance Center**, not in the Fabric admin portal. A security team looking for audit trails needs M365 Compliance access, not Fabric Admin access.

## Capacity Administration

A **Fabric Capacity** is a pool of compute resources (Capacity Units — CUs) purchased via Azure. Capacities are managed separately from Fabric workspaces.

### Capacity SKUs (sizes)
| SKU | CUs | Use Case |
|---|---|---|
| F2 | 2 | Development/testing |
| F4 | 4 | Small teams |
| F8 | 8 | Small production |
| F16–F128 | 16–128 | Medium to large production |
| F256–F2048 | 256–2048 | Enterprise scale |

> **Exam Tip:** Capacity is **not** a Power BI Premium P-SKU in Fabric. The "F" SKUs are Fabric-specific. P-SKUs can be used for Fabric but are being consolidated into F-SKUs. If a question asks about Fabric capacity sizing, it's F-SKUs.

### Capacity Admin Tasks
- Assign/remove workspaces from the capacity
- Scale up or down (change F-SKU)
- Pause and resume capacity (to control cost outside business hours)
- Configure per-capacity settings (Spark pool settings, AI features, etc.)
- Install the **Fabric Capacity Metrics app** to monitor CU consumption

## Workspace Administration

Workspaces are the unit of collaboration in Fabric. Each workspace belongs to one Fabric capacity.

### Workspace Roles (Review)
| Role | Key Permissions |
|---|---|
| **Admin** | Add/remove members, change settings, delete workspace, manage all items |
| **Member** | Add members (up to Member level), create/edit/delete items, share items |
| **Contributor** | Create/edit/delete items; **cannot** add members or manage permissions |
| **Viewer** | Read-only access to all items in the workspace |

> **Exam Tip:** Only **Admin** and **Member** roles can share items externally or add new workspace members. Contributors cannot. Viewers cannot do anything except read.

### Workspace Settings
- **Name and description**: metadata
- **License mode**: which Fabric capacity or Premium the workspace uses
- **Default lakehouse**: for Spark notebooks, which lakehouse is the default catalog
- **Git integration**: connect to Azure DevOps or GitHub for version control
- **Dataflow settings**: configure gateway for on-premises data sources

### Git Integration (Fabric Workspace)
Workspaces can be connected to a **Git repository** (Azure DevOps Repos or GitHub):
- Fabric items are serialised to JSON/YAML in the repo
- Changes can be committed, branched, and reviewed like code
- Enables CI/CD pipelines for Fabric deployments

> **Exam Tip:** Not all Fabric item types support Git integration. Supported items include: Notebooks, Dataflows Gen2, Reports, Semantic Models, Data Pipelines. Items **not** supported: Eventhouse/KQL Databases, Real-Time Dashboards, Activator (as of current releases — check for updates).

## Service Principals

Automated workloads (pipelines, apps) authenticate using a **Service Principal** — an Entra ID application identity rather than a user account.

To use a service principal with Fabric:
1. Register an app in **Entra ID**
2. Enable service principal access in **Fabric tenant settings** ("Allow service principals to use Fabric APIs")
3. Add the service principal as a workspace **Member** or **Contributor**
4. Authenticate using **client credentials flow** (client ID + client secret or certificate)

> **Exam Tip:** Service principal access to Fabric APIs must be explicitly **enabled at the tenant level** by a Fabric Admin. By default it may be disabled. Even if the service principal has workspace permissions, if the tenant setting is off, it cannot access Fabric.

## Monitoring Fabric Workloads

| Tool | Purpose |
|---|---|
| Fabric Admin Portal | Tenant-level settings and user activity overview |
| Fabric Capacity Metrics App | CU consumption per item, throttling detection |
| Microsoft 365 Compliance Center | Audit logs for all user and admin actions |
| Azure Monitor / Log Analytics | Export Fabric logs to Azure for custom alerting |
| Workspace Monitor | Per-workspace pipeline run history, Spark job history |

## Common Exam Traps

**"Workspace Admins can change tenant-level settings"** — False. Tenant settings require **Fabric Admin** (Entra ID role). Workspace admins only control their workspace.

**"Contributors can add new workspace members"** — False. Only Admins and Members can add workspace members (up to their own level).

**"Service principals work automatically once granted workspace access"** — False. The **tenant-level setting** to allow service principal API access must also be enabled by a Fabric Admin.

**"Audit logs are in the Fabric Admin portal"** — False. Fabric activity audit logs are in the **Microsoft 365 Compliance Center** (Unified Audit Log).

**"Pausing a capacity deletes workspace data"** — False. Pausing a capacity stops compute — no data is deleted. Fabric data is stored in OneLake (storage layer) which persists independently of compute.
