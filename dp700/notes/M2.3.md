# Working with Data in Spark DataFrames

This module focuses on the Spark DataFrame API in depth — transformations, aggregations, joins, and working with complex data types. Building on M1.3 (Spark setup) and M2.2 (lakehouse context).

---

## DataFrame Fundamentals

A **DataFrame** is a distributed, tabular data structure with named columns and a schema. It is **lazy** — transformations are not executed until an **action** is called.

| Category | Operations |
|---|---|
| **Transformations** (lazy) | `select`, `filter`, `where`, `groupBy`, `join`, `withColumn`, `drop`, `distinct`, `orderBy` |
| **Actions** (trigger execution) | `show`, `count`, `collect`, `first`, `write`, `display` |

> **Exam Tip:** Transformations build up a **logical plan** (the DAG). Nothing runs until an action triggers the physical execution. This is why chaining many transformations has no performance cost until the final action.

## Column Operations

```python
from pyspark.sql.functions import col, lit, when, upper, lower, trim, round

# Rename a column
df.withColumnRenamed("old_name", "new_name")

# Add a computed column
df.withColumn("TaxAmount", col("ListPrice") * 0.1)

# Conditional column (CASE WHEN equivalent)
df.withColumn("PriceCategory",
    when(col("ListPrice") > 1000, "Premium")
    .when(col("ListPrice") > 500, "Mid-range")
    .otherwise("Budget")
)

# Drop a column
df.drop("UnneededColumn")

# Cast column type
df.withColumn("OrderDate", col("OrderDate").cast("date"))
```

## Filtering

```python
# Single condition
df.filter(col("Category") == "Mountain Bikes")
df.where("ListPrice > 1000")          # String expression also valid

# Multiple conditions
df.filter((col("Category") == "Mountain Bikes") & (col("ListPrice") < 2000))
df.filter((col("Category") == "Mountain Bikes") | (col("Category") == "Road Bikes"))

# Null handling
df.filter(col("Category").isNull())
df.filter(col("Category").isNotNull())
df.dropna(subset=["Category", "ListPrice"])   # Drop rows with nulls in these columns
```

## Aggregations

```python
from pyspark.sql.functions import count, sum, avg, min, max, countDistinct

# Group and aggregate
df.groupBy("Category").agg(
    count("ProductID").alias("ProductCount"),
    avg("ListPrice").alias("AvgPrice"),
    sum("ListPrice").alias("TotalValue")
)

# Global aggregation (no group by)
df.agg(max("ListPrice"), min("ListPrice"))
```

## Joins

```python
# Inner join (default)
joined = orders.join(customers, orders["CustomerID"] == customers["CustomerID"], "inner")

# Left outer join
joined = orders.join(customers, "CustomerID", "left")

# Other join types: "right", "outer"/"full", "left_semi", "left_anti", "cross"
```

**Semi join** — returns rows from left where a match exists in right (no right columns in output)
**Anti join** — returns rows from left where NO match exists in right (useful for "find orphaned records")

> **Exam Tip:** When joining on a column with the **same name in both DataFrames**, use the string shorthand: `join(other, "ColumnName")` instead of `join(other, left["Col"] == right["Col"])`. The string form automatically drops the duplicate column; the expression form keeps both.

## Sorting

```python
from pyspark.sql.functions import asc, desc

df.orderBy("ListPrice")                        # Ascending (default)
```

## Handling Nulls

```python
df.fillna({"Category": "Unknown", "ListPrice": 0.0})  # Fill specific columns
df.dropna()                                             # Drop rows with any null
df.dropna(how="all")                                    # Drop rows where ALL columns are null
df.dropna(thresh=3)                                     # Drop rows with fewer than 3 non-null values
```

## Working with String Data

```python
from pyspark.sql.functions import upper, lower, trim, ltrim, rtrim, split, concat, concat_ws, substring, regexp_replace

df.withColumn("NameUpper", upper(col("ProductName")))
df.withColumn("Code", substring(col("ProductName"), 1, 5))  # First 5 chars
df.withColumn("CleanName", trim(col("ProductName")))
df.withColumn("NameParts", split(col("ProductName"), " "))   # Returns array
df.withColumn("FullDescription", concat_ws(" - ", col("Category"), col("ProductName")))
```

## Working with Dates

## Window Functions

Window functions operate on a **sliding window** of rows rather than a single aggregation. Essential for running totals, rankings, and lead/lag comparisons.

```python
from pyspark.sql.window import Window
from pyspark.sql.functions import row_number, rank, dense_rank, lag, lead, sum as spark_sum

# Define window: partition by category, order by price descending
window = Window.partitionBy("Category").orderBy(col("ListPrice").desc())

# Row number within each category
df.withColumn("RankInCategory", row_number().over(window))

# Running total by order date
window_running = Window.partitionBy("CustomerID").orderBy("OrderDate").rowsBetween(Window.unboundedPreceding, Window.currentRow)
df.withColumn("RunningTotal", spark_sum("Amount").over(window_running))

# Lag (previous row's value) and Lead (next row's value)
df.withColumn("PrevDayAmount", lag("Amount", 1).over(window))
df.withColumn("NextDayAmount", lead("Amount", 1).over(window))
```

## pivot

Transforms row values into columns:

```python
df.groupBy("Category").pivot("Year", [2022, 2023, 2024]).agg(sum("Sales"))
# Produces columns: Category | 2022 | 2023 | 2024
```

Specifying the pivot values explicitly (second argument to `.pivot()`) is much faster than letting Spark discover them — avoids an extra scan.

## UDFs (User-Defined Functions)

Avoid where possible — UDFs break query optimization (they're black boxes to the Catalyst optimizer) and are slow because data must be serialized to Python.

```python
from pyspark.sql.functions import udf
from pyspark.sql.types import StringType

@udf(returnType=StringType())
def classify_price(price):
    return "Premium" if price > 1000 else "Standard"

df.withColumn("PriceClass", classify_price(col("ListPrice")))
```

> **Exam Tip:** Prefer built-in Spark SQL functions (`when`, `case`, `regexp_replace`, etc.) over UDFs. Built-in functions are optimized at the JVM level; Python UDFs require serialization between the JVM and Python interpreter for every row — a major performance bottleneck on large datasets.

**Pandas UDFs** (vectorized UDFs) are significantly faster than regular Python UDFs because they use Apache Arrow for serialization and operate on batches of rows.

## Converting Between Spark and Pandas DataFrames

```python
# Spark → Pandas (brings all data to driver node!)
pandas_df = spark_df.toPandas()

# Pandas → Spark
spark_df = spark.createDataFrame(pandas_df)
```

> **Exam Tip:** `toPandas()` collects ALL data to the driver node. On large datasets this will cause out-of-memory errors. Only use on small/aggregated results. The typical pattern: aggregate in Spark first, then `.toPandas()` for plotting with Matplotlib.

## Common Exam Traps

**"Transformations execute immediately"** — False. Spark uses lazy evaluation. Only actions trigger execution.

**"UDFs are the best way to add custom logic"** — No. Built-in functions are always preferred. UDFs bypass Catalyst optimization and add serialization overhead.

**"`.collect()` is safe to use on any DataFrame"** — No. `collect()` brings the entire dataset to the driver. Use only on small result sets or after significant aggregation.

**"Joining on matching column names using `==` removes duplicates"** — False. Using `left["Col"] == right["Col"]` keeps both columns with the same name, requiring `.drop()` afterward. Use string shorthand to auto-drop the duplicate.
