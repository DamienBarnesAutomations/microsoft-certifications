# Activator in Microsoft Fabric

**Activator** (formerly "Data Activator") is a Fabric item that monitors data streams or tables and **triggers automated actions** when defined conditions are met — without requiring manual monitoring or custom code.

---

## What Activator Does

Activator bridges real-time data and business action:
1. **Watches** a data stream (Eventstream) or a table/semantic model
2. **Evaluates** conditions on each incoming event
3. **Acts** when conditions are met — sends email, Teams message, calls a Power Automate flow, or starts a Pipeline

---

## Core Concepts

### Objects
An **object** is the entity being monitored. Each object has a unique ID (e.g., a machine ID, order ID, device ID). Activator tracks the state of each object independently.

For example, if monitoring IoT sensors, each `DeviceID` is an object. Activator tracks temperature for **each device** separately — if Device A overheats, only Device A triggers the alert, not all devices.

> **Exam Tip:** Objects are identified by a **key column** you specify. Without a key column, all events are treated as a single object and the condition evaluates on the whole stream. With a key column, each distinct key value gets independent state tracking.

### Triggers
A **trigger** defines the condition to evaluate. Trigger types:

| Type | Description |
|---|---|
| **Condition on event value** | Fire when a field crosses a threshold (e.g., temperature > 80) |
| **Change detection** | Fire when a value changes |
| **Pattern: enters range** | Fire when value enters a specified range |
| **Pattern: exits range** | Fire when value leaves a specified range |
| **No activity** | Fire when no events are received for a defined period |

### Actions
When a trigger fires, Activator can:
- **Send email** (via Office 365)
- **Send Teams message**
- **Run a Power Automate flow** (enables complex downstream logic: create tickets, update databases, etc.)
- **Start a Fabric Data Pipeline**

## Data Sources for Activator

| Source | Notes |
|---|---|
| **Eventstream** | Primary use case — direct stream from Eventstream to Activator destination |
| **Power BI semantic model** | Monitor measure values or report data changes |
| **Real-Time Dashboard** | Can connect Activator to detect dashboard anomalies |

> **Exam Tip:** Activator is added as a **destination** in Eventstream — you add an Activator output to an Eventstream just like you would add a KQL database or Lakehouse destination. The Eventstream routes events to Activator continuously.

---

## Activator vs Alternatives

| Requirement | Tool |
|---|---|
| Alert when a metric crosses a threshold in a stream | **Activator** |
| Alert on scheduled report data (daily) | **Power BI alerts** or **Power Automate** |
| Complex event processing with custom logic | **Spark Structured Streaming + custom notification** |
| Trigger a pipeline when new data arrives | **Pipeline Storage Event Trigger** |
| Alert on anomalies in historical data | **Power Automate + Power BI** |

## Setting Up Activator (Typical Flow)

1. Create an **Eventstream** with your source (e.g., Azure Event Hub)
2. Add an **Activator** destination to the Eventstream
3. In Activator, define the **object key** (which column identifies each entity)
4. Add a **property** — the field to monitor
5. Create a **trigger** — the condition and threshold
6. Specify the **action** — who to email/Teams message or which flow to trigger
7. Activate the trigger to start monitoring

---

## State Management in Activator

Activator tracks the **state** of each object between events to support patterns like:
- "Alert only once when condition is first met, not on every event while it's true" (enter/exit patterns)
- "Alert if no data received for 15 minutes" (no-activity pattern)

Without state tracking, every event that meets the condition would fire the action — resulting in alert storms.

> **Exam Tip:** Activator's state tracking means a condition that is **continuously true** will fire the action **once** (on entry), not on every subsequent event. If you need repeated alerts at intervals, use the **recurring** trigger mode.

## Common Exam Traps

**"Activator polls data periodically"** — False. Activator processes events **as they arrive** from the stream. It's event-driven, not polling-based.

**"Activator can only send emails"** — False. It also supports Teams messages, Power Automate flows, and Fabric Data Pipeline triggers.

**"Without an object key, Activator tracks nothing"** — Not quite. Without a key, all events are aggregated as one object — useful for stream-level thresholds. With a key, Activator tracks each distinct entity independently.

**"Activator runs KQL queries"** — No. Activator uses its own trigger/condition model, not KQL. The data arrives via Eventstream; Activator evaluates conditions on each event, not via user-written queries.

**"You configure Activator directly; it has no connection to Eventstream"** — False. Activator is typically added as a **destination in Eventstream**. It receives data from the stream, not from a separate polling mechanism.
