## Activator

**Core Concept**
Activator is Fabric's event detection and rules engine within Real-Time Intelligence — it monitors streaming data against user-defined conditions and triggers automated actions (email, Teams, Power Automate, Fabric item actions) when conditions are met, turning passive monitoring into active response.

**Technical Specifications**
- **Core object model:**
  - **Events:** Individual data records flowing in from data sources.
  - **Objects:** Real-world entities being monitored (Package001, SensorA). Created by selecting a unique identifier field from event data (PackageId, DeviceID). New unique IDs automatically create new objects.
  - **Properties:** Data attributes of objects that are monitored (Temperature, HoursInTransit). Updated continuously as new events arrive.
  - **Rules:** Conditions evaluated against property values, triggering actions when met.
- **Rule definition:**
  - **Monitor section:**
    - **Attribute:** The property to watch.
    - **Summarization:** Average (smooth outliers), Min/Max (catch extremes), Count (track reading frequency, sensor failure detection), Total (sum values).
    - **Timing settings:**
      - **Window size:** How much historical data to include in summarization.
      - **Step size:** How often to recalculate (can differ from window size).
  - **Condition section:**
    - **Threshold monitoring:** Trigger when value crosses boundary.
    - **Change detection:** Trigger when trends increase/decrease from baseline.
    - **Range monitoring:** Track entry/exit from safe zones.
    - **Missing data:** Trigger when no new events for specified duration (sensor failure detection).
    - **Occurrence behavior:** "Every time" for immediate alerts vs. "When it has been true for" for sustained conditions.
  - **Property filter section:** Up to 3 filter conditions to narrow scope.
- **Actions:**
  - **Email:** Detailed notification. Best when immediate response not critical.
  - **Teams:** Immediate channel/individual message. Best for quick team coordination.
  - **Power Automate:** Multi-step cross-system workflows.
  - **Fabric item actions:** Execute data pipelines or notebooks for advanced processing.
- **Alternative alerting approaches (same Activator engine, simpler setup):**
  - **Dashboard alerts:** From Real-Time Dashboard visualizations.
  - **System event alerts:** Monitor Fabric workspace activities and OneLake file operations.
  - **Query alerts:** From KQL Queryset results and visualizations.
  - These do not require the full business objects model.

**Architectural Logic**
Activator's business object model enables stateful monitoring of individual entities — tracking each package's temperature over time, not just checking if any row exceeds a threshold. Summarization (window + step) distinguishes transient spikes from sustained problems, preventing alert fatigue. The property filter section focuses rules on relevant subsets. Alternative approaches (dashboard/query/system alerts) provide simpler paths to the same engine for users who don't need entity-level state tracking.

**Implementation Workflow**
1. Configure Activator as Eventstream destination.
2. Create business objects: select unique identifier, select properties to monitor.
3. Define rule: attribute + summarization (window/step size) → condition (threshold/change/range/missing) + occurrence → up to 3 property filters.
4. Configure action (email, Teams, Power Automate, Fabric item).
5. Save and enable.
6. (Alternative) Create alerts directly from Dashboard tiles, KQL Queryset, or system events.

**Exam Gotchas & Distinctions**
- **Business Objects vs. Simple Alerts:** Business objects track per-entity state (each package's temperature). Simple alerts check conditions against any row in the stream.
- **Window size vs. Step size:** Window = how far back to look. Step = how often to recalculate. They can differ (e.g., 10-min window, 5-min step).
- **Summarization prevents alert fatigue:** Averaging over windows catches sustained problems, ignoring brief fluctuations.
- **Missing data detection:** Configure to detect sensor failures, not just threshold violations.
- **Up to 3 property filters:** Combine for precise targeting.
- **"Every time" vs. "When it has been true for":** "Every time" fires on each qualifying event. "When true for" waits for sustained condition over time period.
- **Fabric item actions execute Notebooks/Pipelines:** Enables automated data processing loops without human intervention.
- **Power Automate for cross-system workflows:** Use when action involves multiple systems (email + CRM + ticket).
- **Alternative alerts use same engine:** Dashboard alerts, query alerts, system event alerts all use Activator but skip the business object setup.
