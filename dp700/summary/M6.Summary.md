# Module 6: Activator

## Card 1: Activator

### What It Is

Activator is Fabric's built-in event detection and rules engine within the Real-Time Intelligence solution. It monitors your data streams in real time and automatically triggers actions when specific conditions are met, allowing you to respond to events as they happen without manual intervention.

### Key Details

#### Core Object Model

Activator is built around four core concepts. Events represent individual data records flowing through your eventstreams. Objects are the real-world entities you are monitoring, such as a specific temperature sensor in a factory. Properties are the data attributes associated with each object, like temperature readings or pressure values. Rules are the conditions you define that trigger actions when satisfied.

#### Creating Objects from Eventstreams

You configure Activator as a destination on your eventstream, then choose a unique identifier property that distinguishes each object. You select which properties to monitor, and any new unique ID that appears in the stream automatically creates a new object in Activator.

#### Rule Definition with the Monitor Section

The Monitor section defines what Activator watches and how it summarizes data. You choose an attribute to watch and select a summarization method. Average smooths outliers to give you a stable trend view. Min and Max catch extreme values that may indicate problems. Count tracks how frequently readings arrive, which helps detect sensor failure when readings stop. Total sums values over time.

You also configure timing with two parameters. Window size determines how much historical data to include in the summarization. Step size determines how often the summarization is recalculated. These two values can differ, giving you flexibility in how you monitor trends versus how frequently you evaluate them.

#### Condition Section

The condition section specifies when a rule fires. Threshold monitoring triggers when a value crosses a defined limit. Change detection fires when a value changes significantly. Range monitoring triggers when a value falls outside an acceptable range. Missing data detection is useful for identifying sensor failures when readings stop arriving.

For occurrence behavior, you can choose "Every time" for immediate alerts on every qualifying event, or "When it has been true for" to require that a condition remains true over a sustained period before firing, which helps avoid false alarms from brief spikes.

#### Property Filter Section

You can apply up to three filter conditions to narrow the scope of what a rule monitors, ensuring actions only trigger for the specific objects or situations that matter to you.

#### Actions

When a rule fires, Activator can execute several types of actions. Email sends detailed notifications to specified recipients. Teams posts immediate messages to a channel for rapid team response. Power Automate enables multi-step, cross-system workflows that can span multiple services and applications. Fabric item actions execute pipelines, notebooks, or other Fabric items directly.

#### Alternative Alerting Approaches

Beyond full Activator object-based rules, Fabric offers simpler alerting options. Dashboard alerts let you set thresholds on visualizations. System event alerts notify you of platform-level events. Query alerts run on the same Activator engine but require simpler setup and do not need business objects, making them a lighter-weight option for straightforward monitoring scenarios.

### Exam Gotchas

Activator requires a Real-Time Intelligence capacity or Fabric F SKU to function. Remember that window size and step size are independent parameters and can be set to different values, which is a common exam question. The "When it has been true for" condition is designed to reduce false positives from transient spikes, so it is the preferred choice when sustained conditions matter more than momentary breaches. Query alerts use the same Activator engine under the hood but do not require you to define business objects, so do not confuse the two approaches on the exam.
