# M6.1.md

## Core Concept
Activator is Microsoft Fabric's event detection and rules engine within Real-Time Intelligence that automatically evaluates conditions in streaming data to trigger specific actions.

## Technical Specifications
*   Configuration Model (Business Objects):
    *   Objects: Individual instances being monitored (e.g., PackageId, DeviceID).
    *   Properties: Attributes of those objects (e.g., Temperature, DeliveryState).
    *   Events: Incoming data records that update object properties.
*   Rule Definition (Definition Pane):
    *   Monitor: Selects an Attribute and applies Summarization (Average, Min/Max, Count, Total) with Window size (historical data range) and Step size (recalculation frequency).
    *   Condition: Detection logic (Threshold monitoring, Change detection, Range monitoring, Missing data) and Occurrence behavior (Every time vs. "When it has been true for X minutes").
    *   Property Filter: Narrow scope using up to three filters (e.g., `City == "Seattle"`).
*   Actions:
    *   Email: Detailed context for non-immediate response.
    *   Teams: Immediate messages for rapid coordination.
    *   Power Automate: Multi-step cross-app business processes.
    *   Fabric Item: Executes data pipelines or notebooks for further analysis.
*   Alternative Alerting: Dashboard alerts (from visualizations), System event alerts (workspace/OneLake activities), Query alerts (from KQL Queryset).

## Architectural Logic (The "Why")
Activator transforms passive monitoring into active response. By utilizing a business object model, it can track individual entities over time rather than just viewing data as a generic stream. Summarization is critical to filter out "noise" (brief spikes/dips) and detect sustained, meaningful conditions.

## Implementation Workflow
1.  Connect Activator as a destination for an Eventstream.
2.  Define Business Objects: Select a unique identifier and the properties to monitor.
3.  Create a Rule:
    *   Set Monitor attributes and summarization parameters.
    *   Define the Condition (threshold/trend) and the duration it must be true.
    *   Apply Property Filters to target specific subsets of data.
4.  Configure Actions: Select the notification or automation method (Email, Teams, Power Automate, Fabric Item).
5.  Save and enable the rule.

## Exam "Gotchas" & Distinctions
*   Activator focuses on *detecting conditions* and *triggering actions*.
*   Business objects allow tracking of *individual instances* (e.g., a specific sensor) rather than just the stream as a whole.
*   Window size vs. Step size: Window is the "look-back" period; Step is the "update" frequency.
*   Difference between an "Action" (e.g., Email) and a "Rule" (the logic that triggers the action).
*   Alternative alerting paths (Dashboard, System, Query) use the same engine but different input triggers.
